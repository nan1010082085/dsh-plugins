# idea-to-drama（想法原创 · 分集编剧）

把用户的想法（一句话到一段）原创成分集剧本条目。**根原则：由想法出发进行创作**——
用户想法是唯一事实源，创作 = 提炼 + 校准 + 补完成戏，不偏题不注水；想法的核心要素必须在剧本里有落点（想法命中率），不许脱离想法自创。

参考文件（规则引用，不复述全文）：

- `shared/split-methodology.md` —— 拆分与改编方法论（换算锚/故事单元/每集结构模板/两核心验收），分集规则的唯一真相源，原创分集同用
- `shared/output-formats.md` —— LOCKED 剧本条目契约，字段名逐字引用（`集数` / `时长秒` / `场景节拍[]` / `人物[]` / `本集看点` / `结尾钩子`）
- `shared/hard-gates.md` / `shared/lessons.md` —— 硬闸总纲与历史翻车点
- `shared/script-standard.md` —— **剧本内核参考**（内核五条：魂/反差/幽默温情/电影语言/设定服务叙事 + 七段式载体建议），故事灵魂的参照系——**吸收 DNA 不抄格式**
- `shared/script-craft.md` —— **剧本文风与叙事技法**（好坏对照/技法七条/三稿制/可读性验收），剧本质量的唯一真相源
- `references/idea-workflow.md` —— 原创操作细则（想法提炼提问模板；搜索关键词构造法；logline 模板；多集结构与集数规划；人物小传字段；两核心验收——含想法命中率）

## 何时使用

- 用户丢来一句话到一段的想法（脑洞/设定/桥段/人设），要求原创漫剧/短剧、出分集剧本。
- 用户要求把想法扩成 logline、多集结构、人物小传，或做集数规划。
- 用户要求按市场偏好反推选题/冲突结构，或校准某题材的爆款打法。
- 下游 `storyboard-director`（剧本条目 → 分镜块）的上游前置；小说改编走 `novel-to-drama`，本 skill 只走原创路径。

## 流程

### 第 1 步：需求澄清（最多追问 2 问）

先读想法本身，四个意向位：**题材 / 受众 / 单集时长意向 / 集数盘子**。

- **最多追问 2 问**（提问模板见 `references/idea-workflow.md` 第一节）；能从想法词面读出的意向位不再问。
- **缺的自己推理补默认并声明**：每个补位输出一条「假设：…（依据：…）」，用户可改；不许拿追问刷屏，也不许闷头替用户做主不吭声。
- 默认值参考：题材从想法词面推；受众默认女频向 25–44（25–34 核心、35–44 第二主力；题材指向男频则改）（2026-10-31 校准：原「女频 18–35」，35–44 第二主力被整个切掉——【行业报告·艾媒+明略+DataEye】，见 `references/idea-workflow.md` §八）；单集时长意向默认不设、走正片 60–120 秒自动成型；集数盘子默认一季 5–10 集量级、按故事单元自然成型。

### 第 2 步：搜索（联网检索校准）

按想法的题材检索三类信息，检索关键词策略见 `references/idea-workflow.md` 第二节（**题材词 + 冲突词 + 平台词**三段式）：

- **同类题材**：近期同题材爆款/高播放作品，看它把什么桥段做成了名场面；
- **爆款冲突结构**：该题材吃香的冲突密度、反转节奏、钩子套路；
- **市场偏好**：目标受众的口味与完播点（开头多久进冲突、哪类钩子留人）。

检索之外有**市场校准基线**兜底（`references/idea-workflow.md` §八，2026-10-31 入库）：完播驱动 TOP3 = 故事设定 > 剧情节奏 > 制作质量【行业报告·明略 2026】；完播率是平台算法二次推荐的核心硬指标，「集内钩子保点击、整集质量保完播」【官方媒体·文汇报/光明网】。检索不可用时按基线校准并声明。

搜索结果只做校准参考——**拿来的是「什么冲突/什么钩子吃香」，不是别人的故事**；禁抄设定、禁搬运情节、禁引名台词。检索不可用或搜不到时，用通用戏剧常识补位并声明「未检索到，按通用套路校准」。

### 第 3 步：戏剧结构（logline → 多集结构 → 人物小传）

1. **logline**：主角 + 目标 + 阻碍 + 赌注，一句话定盘（模板见 `references/idea-workflow.md` 第三节；业界共识四件套，单句约 35 words、中文建议 ≤80 字【专业媒体·Creative Screenwriting/Final Draft】，中文折算标【经验·内部】）；logline 必须罩得住想法核心要素。
   **内核一句话（动笔前置，`shared/script-standard.md` 内核第 1 条）**：答得出「这故事真正讲什么」（主题/魂，如「孤独的灵魂渴望陪伴」）——答不出不动笔，情节全程为内核服务。
2. **多集结构**：建置 → 升级 → 高潮，逐集按每集结构模板落位（`shared/split-methodology.md` 第四节，引用不复述）；**集数按故事单元自然成型**——一集一个微事件，装不下拆、装不满并，禁为凑集数摊薄故事、禁为省集数硬压。
3. **人物小传**：主角/配角/路人三级，字段与 `shared/output-formats.md` 的 `人物[]` 呼应，逐人命名可挂资产（说话方式/性格特征逐人记下，供剧本「人物靠对话」用）。

### 第 4 步：分集剧本（两核心同时成立）

逐集写剧本条目（字段契约见 `shared/output-formats.md` 第 1 节），验收看两核心（细则见 `references/idea-workflow.md`）：

- **灵活叙事**：冲突密度高、砍水戏、每场戏直接可拆镜头，产出即进分镜不返工；
- **剧本理解（原创版 = 想法命中率）**：用户想法的核心要素逐条在剧本里有落点，扩写补完不偏题，不许悄悄换成另一个故事。

硬性写法：**黄金秒链**——起手 3 秒钩子（直接冲突/强悬念/极致反差三型）、10 秒内立矛盾、30 秒内首爆点、每 20–30 秒一个情绪节点（原「开头 5 秒抓人」并入链口径，2026-10-31 校准）【社区·数艺社/DramaSo＋官方媒体·文汇报佐证完播口径】；结尾必留钩子（Cliffhanger），且第 N 集悬念 = 第 N+1 集钩子；人物靠对话和选择体现性格，禁旁白交代；叙述→视听（心理描写转动作/表情/潜台词）。

**剧本深度标准（2026-10-27 用户令：几行节拍不算剧本；载体与内核见 `shared/script-standard.md`——七段式为载体建议可裁剪，内核五条为硬要求）**：每集必须含「分场叙事」节——逐场戏 **300–500 字画面叙事**（环境/动作/表情/光影/道具/声音写满，能直接喂分镜、能读出故事），台词带语气标注，音效/环境声逐场标注，末尾带转场备注。只有节拍+台词占位 = 提纲，打回重写。

**三稿制（2026-10-27 用户令：剧本必须可读，结构合格≠剧本合格）**：初稿（结构）→ 精修稿（按 `shared/script-craft.md` 文笔技法逐场精修：五感开场/动作链/对白两层/节奏呼吸/删废话）→ 定稿（**人读五问验收**：通读不卡壳/有画面/有情绪/台词是人话/钩子在场，逐集签字）。一稿交付=违规，提纲式输出=废稿。文风好坏对照与技法唯一真相源：`shared/script-craft.md`。

**时长自动成型**：每集 `时长秒` 由节拍与分镜自然得出，正片 60–120 秒区间，不硬凑不牵强——不为凑时长注水、不为压时长砍戏；30–60 秒只用于引流切片，不作正片集（2026-10-31 校准：原 30–120，30 秒下限低于主流口径——【社区共识·DramaSo/数艺社】，平台规则明文未见）。

## 硬闸与自检

- **想法命中率**：想法核心要素逐条列出、逐条在剧本里有落点；缺落点 = 打回第 3 步补结构，不许带偏题交付。
- **集数/时长自然成型**：集数按故事单元自然成型，`时长秒` 正片 60–120 自动（30–60 秒仅引流切片）；注水、硬凑、摊薄凑集数都算分集失败（`shared/split-methodology.md` 第一、二节）。
- **前三集生死线**：64.1% 受众三集以内弃剧，第 3 集必须有小爆点；中后期弃剧负面 73.5% 集中于「剧情逻辑崩塌/人设矛盾」——人物动机链与逻辑连续性是留存硬指标【行业报告·明略 2026】（`references/idea-workflow.md` §八）。
- **看点/钩子句号收尾**：`本集看点`、`结尾钩子` 各一句话、句号收尾；钩子不在场 = 该集不定稿。
- **连贯检查过才定稿**：每集开头承接上集 + 结尾钩子在场 + 主线贯穿（`shared/split-methodology.md` 第四节）。
- **搜索不搬运**：市场调研只校准冲突密度与钩子打法，禁抄同题材作品的设定/情节/名台词；搜索不可用必须声明。
- **人物可挂资产**：`人物[]` 逐人对齐 assets.json 的 `characters.name`，露脸角色全挂；性格靠对话不用旁白。
- **品牌三层都禁**：剧本的台词/旁白/字幕文案不得出现真实品牌（`shared/hard-gates.md` 第 6 节，交付前过 `tools/brand_scan.py`）。
- **不烧积分**：本 skill 只产剧本，不执行生成；出图/出片必经花钱门与 Notion 审核（`shared/hard-gates.md` 第 1、2 节）。
- 违禁废话词、翻车点对照 `shared/hard-gates.md` / `shared/lessons.md` 通读一遍再交付。

## 产出与格式

- **产出四件**：
  1. **logline**：主角 + 目标 + 阻碍 + 赌注，一句话；
  2. **集数规划表**：集数 / 微事件一句话 / 预估看点——集数按故事单元自然成型，不是先定集数再切故事；
  3. **人物小传表**：姓名 / 三级定位 / 目标与阻碍 / 说话方式（与 `人物[]` 呼应）；
  4. **剧本条目数组**：每集按 `shared/script-standard.md` 七段式载体（故事背景/风格核心/故事内核/人物设定/场景设定/道具设定/**故事内容**——叙事散文体为本体）+ 头部元数据行（LOCKED 字段 `{集数, 时长秒, 场景节拍[], 人物[], 本集看点, 结尾钩子}`，供下游机器读取）。内核五问验收（`shared/script-standard.md` §四）逐集签字。
- **场景节拍[]**：元素为 `{目标/冲突, 起承转合, 钩子}`（字段名含斜杠，照写）；哪怕很短，起承转合也要齐。
- **时长秒**：正片 60–120，自动——由节拍与分镜自然成型，不硬凑（30–60 秒仅引流切片）。
- **人物[]**：本集出场人物名，与 assets.json 的 `characters.name` 对齐，逐人可挂资产。
- **本集看点 / 结尾钩子**：各一句话，句号收尾。
- 约束：单集 1–3 个场景、一集一个微事件、全局集数连续。
- **想法命中对照**：交付时附一张「想法要素 → 落点集数」对照表，供用户核对没偏题。
- 下游衔接：剧本条目交 `storyboard-director` 产分镜块（`shared/output-formats.md` 第 2 节）；字段名冲突时以契约为准，改文案不改契约。
