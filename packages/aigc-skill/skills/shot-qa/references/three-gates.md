# 三道闸操作细节（three-gates）

> shot-qa 每次出片检查逐闸执行，任一 FAIL 打回对应环节重做，禁止带病出片。
> 字段名以 `shared/output-formats.md` 为唯一真相源；本文件只写「怎么查」，契约字段不改名。

## 闸 1：价格闸（花钱门）——报价单格式与批准记录法

### 报价单格式

用 `tools/credit_gate.py` 的 `quote(cmd)` 干跑报价（返回 `{total_max_credits, items}`），账单按下面格式发给用户：

```
【账单】<剧名/集号> 生成报价
- [镜号/项目] 单价 × 数量 = 小计
- [镜号/项目] 单价 × 数量 = 小计
总价上限：X 积分（按实估上限，含档位差余量）
请明确批准（批准人 + 上限）后才会执行；实际支出逼近上限会停下重新报价。
```

- **quote ≠ run**：`quote` 报价可能显著低于实估（seedance 档位差，`shared/lessons.md` 第 6 条），账单必须按**实估上限**报、留余量。
- 逐镜报价：镜多时逐镜列单价 × 数量，汇总到总价上限；报价失败/无上限一律抛错，禁止静默报 0。

### 批准记录法

- 批准 = 用户**明确回复**「批准」+ 批准人 + 批准上限；写进检查报告的 `价格闸.批准`。
- 审查通过 ≠ 批准花钱——内容对不对和批不批花钱是两件事；批量/重制尤其禁止「反正内容过了就自己开跑」。
- 执行：`credit_gate.run(cmd, approved_by, max_credits)`——`approved_by` 为假值（None/空串）直接 `PermissionError`，**缺批准信息一律拒绝执行**；执行时自动剥离命令里预置的 `--credit-ceiling`，花钱门独占 ceiling。
- **超账单重新批**：实际支出逼近或超出已批上限，立即停下 → 重新 `quote` → 重新获批 → 才许续跑；禁止拿旧批文硬跑。

## 闸 2：分镜剧情校验——逐项检查法

### 逐字（SHA-256 级对账）

出片指令必须与剧本/Notion 原始指令**逐字一致**（零压缩搬运，`shared/hard-gates.md` 第 3 节）。对账命令示例：

```bash
# 双方同一方式提取纯文本（如剥掉 Markdown 标注头后取正文）
printf '%s' "$(cat notion_raw.txt)"   | shasum -a 256
printf '%s' "$(cat prompt_payload.txt)" | shasum -a 256
# 两值一致 = 逐字搬运过闸；不一致 = 被压缩/改写/拼装/加删标注头 → FAIL，打回逐字搬运
```

- 空白/换行归一化必须**两边同一处理**，禁止一边归一一边不归一制造假一致。
- 本地拼装指令再传、把多段合成一段、给指令加删标注头——全部 FAIL（`shared/lessons.md` 第 10 条）。

### 转场判定与通过标准

- **转场点判定**：相邻两镜的场景标签（分镜块 `六要素.场景`）发生变化，后一镜即转场点/进场镜，必须带 `转场交代`。
- **通过标准**（三件套齐，缺一即 FAIL）：
  1. 时间交代（旁白或屏幕 UI 字幕卡）；
  2. 地点交代（同上）；
  3. 转场过渡句——明写空间延续（镜头从上场景空间延续摇入/推入等），**明写不硬切**。
- 同场景多镜共用同一套场景资产（空间/光影连贯）；镜文没写 = 模型自由发挥 = 转场突兀，裸切直接打回（`shared/lessons.md` 第 8 条）。

### 品牌三层扫（画面 / 语音 / 字幕）

```python
from tools.brand_scan import scan_shot, scan_text
hits  = scan_shot(画面, 台词旁白弹幕)   # 画面层 + 语音层（台词/旁白/弹幕）
hits += scan_text(字幕文本)             # 字幕层单独扫
```

- 词表 `shared/brand-wordlist.txt`（真实品牌名 + 品牌感包装词）；三层任一命中 = FAIL，禁止「化名绕过」。
- 指令里商品写死「素色无品牌 + 禁包装特写」，Logo/商标字样同样禁（`shared/hard-gates.md` 第 6 节）。
- **极限词扫描（2026-10-31 入库）**：台词/字幕/贴片里的品牌宣传语扫极限词——「国家级、最高级、最佳」及近似用语为红线【官方：《广告绝对化用语执法指南》市监总局 2023】；六类豁免情形（经营理念/主观愿望、同品牌自我比较、消费提示、商品名称或注册商标本身、评定奖项称号、限定时空销量事实）可对照放行，医疗医美/药品保健食品/招商投资/教育培训从严；品牌露出须具**广告可识别性**【官方：视频号 4.6.4】，隐性营销违规。

### 违禁与细节下限

- **违禁废话词**：走 `tools/prompt_selfcheck.py`（4K / 8K / 杰作 / 超清晰 / 大师作 / wallpaper），命中即 FAIL，换物理材质词。
- **内容违禁扫描范围与判定标准（2026-10-31 入库）**：扫描范围=画面 / 台词 / 旁白 / 字幕 / **标题 / 话题 / 弹幕**（细则总则：标题、名称、评论、弹幕、表情包都在审核范围；视频号 5.5.1 标题惊悚词同管【官方】）；惊悚/微恐/血腥判定用**效果标准**——是否可能引发普通观看者惊恐、焦虑、厌恶、恶心等不适，**非词面匹配**【官方：细则 62 条、视频号 5.2.5/5.13.1、快手第四章二】；官方明文禁区示例（骷髅/尸体/密集恐惧/自杀自残/枪击/刺伤/拷打/恐怖灵异）逐项拦截，条款全表见 `shared/hard-gates.md` 第 11 节。
- **每镜 ≥250 字**：正文细节计数（去标题与空白后），不足 = 打回 `storyboard-director` 补写。
- **看点/钩子句号收尾**：剧本条目 `本集看点` / `结尾钩子` 必须一句话、句号收尾；其关键词在镜内有落点（看点词落镜内、钩子落在结尾镜）。批量核验可跑 `tools/pre_gen_gate.py`（G3 剧情核验，字面不中时须附镜内原句当实质落点证据，禁止为塞关键词改写剧本）。

## 闸 3：素材校验——挂载矩阵审查与验真

### 挂载矩阵审查（对照 output-formats 素材映射）

以分镜块 `素材映射[]` 为清单，逐镜对账 assets.json（`shared/output-formats.md` 第 3 节）：

| 检查项 | 对照源 | 通过标准 |
|--------|--------|---------|
| 露脸角色挂载 | `characters[].name / visual_id` | 露脸角色全挂（含对手戏，`shared/lessons.md` 第 13 条），每人都有对应资产 |
| 场景挂载 | `scenes[].名 / image` | 场景必挂；同场景多镜共用同一套场景资产 |
| 表情/服装 | `expressions[] / outfits[]` | 该镜用到的表情/服装套同源，无漂移（`shared/lessons.md` 第 3 条） |
| refs 数量 | `素材映射[]` 条目 | ≤9（元素过载本就该拆镜） |

### 格式与节点状态

- ref ID 必须匹配 `node_[a-z0-9]{10}`（身份锚 visual_id 同格式）。
- 节点存在且状态 **success**；场景图必须**纯空镜**（有人场景不能用于出视频）。

### 验真流程（只认新资源）

1. **提交时间戳记账**：执行生成（`run`）前记下提交时刻。
2. **取新资源**：生成后看 **`submission.resources`**，不看 node 旧快照。
3. **createdAt 比对**：新 resource 的 `createdAt` 必须**晚于**本次提交时间戳才算本次结果；历史 success 资源一律不得当结果汇报（`shared/lessons.md` 第 7 条）。
4. 轮询等待必须等新 resource 出现，禁止抓节点上第一条 success 交差。
5. Notion 侧的生成状态与资源查询走 `tools/notion_mcp_client.py`（`MCP().call(...)`）；生成状态 ≠「生成中」时禁止出图/出视频（`shared/hard-gates.md` 第 2 节）。

配套纪律（`shared/hard-gates.md` 第 5 节）：一枪一停（出完验完再开下一枪）、原节点重跑（重试不换指令不另起炉灶）、重制不夹带（只重制目标产物）。

## 检查报告填写模板（LOCKED 字段）

字段名逐字引用 `shared/output-formats.md` 第 4 节，**禁止改名、别名、增删字段**：

```
检查报告{
  价格闸{
    报价: 过/FAIL——逐镜报价（单价×数量）+ 账单上限 X 积分，证据一句话
    批准: 过/FAIL——批准人 + 批准上限 + 批准时间；未批准=FAIL 不得出片
  },
  剧情校验{
    逐字: 过/FAIL——SHA-256 对账一致/不一致（贴两串哈希前 8 位）
    转场: 过/FAIL——转场镜清单，逐镜写三件套齐/缺哪件
    品牌: 过/FAIL——三层扫描命中数（画面/语音/字幕各写命中词）
    违禁: 过/FAIL——违禁词命中、<250 字镜号、看点/钩子收尾情况
  },
  素材校验{
    挂载: 过/FAIL——逐镜挂载齐/漏挂谁（人/场景）
    格式: 过/FAIL——ref 格式与节点 success 核对结果
    验真: 过/FAIL——提交时间戳 vs 新 resource createdAt 比对结果
  }
}
```

- 每项写「过 / FAIL + 一句话证据」；FAIL 项写明打回哪个环节、改什么。
- **三闸全过才准出片**；有 FAIL → 打回对应环节（分镜 → `storyboard-director`、素材 → `character-studio` / `scene-studio`、剧本 → 剧本 skill）重做后再检。

## 交付清单填写模板（AI 标识 · 法定义务，交付/发布前）

> LOCKED 检查报告之外的法定义务附加项（`shared/hard-gates.md` 第 10 节）。**官方，最高优先级**：《人工智能生成合成内容标识办法》（国信办通字〔2025〕2 号，2025-09-01 施行）+ 视频号 6.4。任一 FAIL 拒绝交付/发布。

```
交付清单{
  AI 标识{
    显式: 过/FAIL——视频起始画面+播放周边显著提示核对；导出文件含显式标识
    隐式: 过/FAIL——文件元数据（生成属性/服务提供者/内容编号）核对
    发布主动声明: 过/FAIL——发布声明与平台标识功能使用核对；无删除/篡改/伪造/隐匿标识
  }
}
```

- 素材层关水印（`watermark=false`，`shared/backends.md`）≠ 成品免标识——发布成品的显式标识义务本清单兜底。
