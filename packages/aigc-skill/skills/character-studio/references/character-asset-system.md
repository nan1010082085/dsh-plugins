# 人物资产规范（三视图锚点制 · 人物侧）

> 「人物资产怎么建、怎么出图、怎么登记」。字段名逐字引用 `shared/output-formats.md` §3 LOCKED 契约：
> `characters:[{name, visual_id, three_view, face_card, expressions[], outfits:[{名, three_view, 配饰}]}]`。字段改名诉求一律回 output-formats.md 提。

## 一、人物资产台账

| 字段 | 含义 | 建法要点 |
|------|------|---------|
| `name` | 角色名 | 与剧本条目 `人物[]`、分镜块 `素材映射[]` 逐字一致 |
| `visual_id` | 身份锚 ref | `node_`+10 位小写字母数字；注册后不换、不复用 |
| `three_view` | 主体三视图（身份锚，**永久**） | 锁脸/身材/头身比；**中性基础款服装**；t2i；定稿即锁 |
| `face_card` | 面部身份卡/色卡 | 面部特写+色卡（主色/发色/瞳色/肤色调） |
| `expressions[]` | 表情表数组 | i2i 挂主体；每格只写表情解剖（眉/眼/嘴/神态收束 25–40 字） |
| `outfits[]` | 服装套数组 | 可替换模块，见 §三 |

## 二、生成规范（t2i / i2i 分工）

### 主体三视图 = 身份锚（t2i）

- **锁定对象**：脸、身材、头身比——永久；服装只穿**中性基础款**（服装是模块，不焊进身份）
- **t2i 文字控构图**：三视图构图靠提示词写死（并排/同站姿/同机位/脚底同基线/纯浅灰底）；i2i 垫图会锚死视角景别（lessons 第 1 条）
- **三张视图同条件（社区实测：Arcloop 三视图手册 + mooko）**：同站姿——肩平放松、头正、**双臂稍离躯干**（手臂与躯干留少量空隙、露手部与服装轮廓），禁耸肩/歪胯/夸张动作，A-pose/T-pose 仅流程明确需要时用；同身高尺度、**脚底对齐同一基线**；机位=**正交/真侧视（true side profile）、避免夸张透视**（原「同相机高度」按外部口径改述）；同光照=**均匀光**；**头顶与鞋全入画留余量**、纯色浅背景
- **先补看不见的部分**：后领、衣长、背面接缝、不对称细节（发夹/挎包/伤疤在角色自身哪一侧）先写死再出图
- **先锁脸再全身（社区实测：Arcloop）**：脸特写/面部卡必须从已确认设计派生（i2i 挂已锁主体或同图内加格），禁止补特写时重新生成五官——补特写只为把已确认的设计看得更清，不是重新设计
- **随身道具默认不进三视图（社区实测：Arcloop）**：包/手机/武器等随身物走 prop-studio 单独出图，使用者/拿法写进分镜描述；已属服装结构的刀鞘/枪套/背带可留在身上
- 定稿后写入 `visual_id` 节点并**锁定**，永不再改

### 服装三视图 / 表情表 / 立绘 = 模块（i2i 挂主体）

- 一律 i2i 挂主体三视图，强制**同光影、同站姿、同机位、同身高比例**——换的只有服装/表情
- **构图硬锁句必备**：`单人单图、正常站姿`（防视角被锚走）。参考图排版压不住，用画框锁（2026-10-28 xyq 实测）——单人格画框锁（正面画框描述）见 `character-prompts.md` §1.7
- 表情表：外貌/年龄/妆感/背景/风格只在布局头写一次，每格只写表情解剖、写满写差异；禁 6 字碎片、禁每格抄全外貌
- **表情表定位（社区实测：Arcloop）**：表情表是人工审阅/绘制参照与镜头表情描述素材，**不自动提升视频/跨镜一致性**——复杂参考表不会自动赋予一致能力；常规表情直接写进出图/出视频 prompt，特别夸张、模型难理解的表情才提供表情参考（一致性真实边界见 §五）
- 单人立绘（视频 ref 用）同规则；设定图/三视图永远不是视频素材（lessons 第 5 条）

## 三、多套服装规则

1. **逐件写死**：上装版型+颜色+面料、下装、鞋袜、配饰逐件写死——只写「休闲装」必漂（卫衣漂裙装教训）
2. **配饰拆解**：`配饰` 逐件登记「名称+佩戴位置+角色自身左右」；不对称配饰允许自然遮挡、禁止换边、禁止整图镜像
3. **命名**：`名` 用「剧情语义+关键件」（如「校服常服·深青外套」），一套一图一登记；文件版本命名用 `character-XX_阶段_服装_vNN`（社区实测：Arcloop）
4. **同源铁律**：分镜块该镜服装描写与该套服装提示词段**同源**（同一套词）；换装出图后回写 `outfits[]`，与 `素材映射[]` 对账
5. i2i 同光影/站姿/机位（§二）：服装三视图与主体三视图并排比对时只有衣服在变
6. **每套独立审阅（社区实测：Arcloop）**：每套服装/年龄段独立生成、独立审阅、独立命名存档——「不是对模型一致性的承诺」；逐套核对三视图对应（领口/袖长/腰线/裙褶/裙摆/鞋子）后入库
7. **服装变体表公式（社区实测：Krea）**：角色描述恒定、只有每格服装变（"the same original character shown in five outfits" 式）；配色 3–5 个色彩词全表复用——palette drift 是不一致最大成因

## 四、一致性硬规则（出图逐条自检）

1. 每图复述同一组固定特征短语（脸型/发型/瞳色/辨识配饰/国籍）+「细节一致，无变化」
2. 主体 t2i；模块 i2i 挂主体 + 构图硬锁句
3. 角色写国籍（中国角色明写「中国面孔」），防出欧美脸
4. 生图只写固定景别，不写运镜词
5. 露脸角色全挂、双人镜逐人挂（`shared/lessons.md`）
6. 术语准确、特征具体（「银色短发狼尾」而非「好看的发型」）
7. 不对称细节写死角色自身左右
8. **广告闸**：手持物/商品「素色无品牌+禁包装特写」，过 `tools/brand_scan.py`
9. 重制不夹带；扣积分走花钱门
10. **配色一致性（社区实测：Krea）**：每角色固定 3–5 个色彩词全表复用（主色/发色/瞳色/常用服色），「palette drift 是不一致最大成因」

## 五、一致性真实边界（外部印证，出图前后都看）

- **参考式 ≠ 身份锁**：即梦多参考图/图生图 ≈ IP-Adapter 式「参考条件」，天花板=视觉近似不等于身份保证——IP-Adapter 原论文只承诺图像提示能力（官方论文：arXiv 2308.06721）；FaceID 官方自认纯 IP-Adapter 的 ID 一致性不够、要 +LoRA 补强（官方：tencent-ailab/IP-Adapter wiki）
- **角色 LoRA 天花板最高**：25–40 张图多角度训练在超一致性上「没有对手」，大角度/多角度下比参考式更稳（社区实测：aiofm / loradataset 横评）；通行组合=参考式生成攒数据集 + LoRA 出片
- **复杂参考表不自动赋予一致性（社区实测：Arcloop）**：「不要把『参考图里已经画清楚』当作『视频一定能够还原』」——纹身/疤痕/配饰跨镜仍可能丢、变形、换边；生成后必须人工核对配饰换边/丢疤/变色，崩坏镜单独重生成
- **站方承诺边界（社区实测：Krea）**：多视图「visually consistent, not pixel-perfect」——要像素级先出正视图，再以它为 image reference 出其他视图
- **流程兜底才是保证（经验·内部）**：设定卡为唯一入口 + 每镜挂资产 + 崩坏镜重生成（`shared/lessons.md`）——模型不承诺，流程承诺
