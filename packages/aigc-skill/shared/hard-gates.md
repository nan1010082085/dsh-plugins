# 硬闸总纲（hard-gates）

> 2026-10-27 定案｜适用范围：五个 skill 的**全部**产出与生成动作。
> 每条闸标注主责 skill；无论主责是谁，任何 skill 触发生成前都必须逐条自检。**任一闸不过 = 拒绝出图/出片，退回修改。**
> 这里的规则来自漫剧实战逐条验收过的硬闸，是本套件的最高约束；与单个 skill 文案冲突时以本文件为准。

## 最高原则：校验=合规，不是限创作（2026-11-05 用户令）

所有产出、检查、校验只拦**合规风险**，不拦**创作发挥**：

- **拦（合规）**：平台审核违禁词与惊悚浓度、品牌植入三层、AI 标识法定义务（闸 10）、未批烧积分、指令压缩搬运失真、素材漏挂/错挂浪费积分、拼装手误、机器可读底线
- **不拦（创作）**：字数无上下限、风格/叙事/镜头语言自由、模型能力范围内任意发挥；检查报「缺料」只提示补细节，不规定怎么写
- **判定口径**：每个检查项必须能回答「不拦会有什么合规/资损后果」——答不上来的检查项=创作枷锁，删掉或降级为提示

## 零容忍清单（做了即失败）

- 「塑料 AI 感」提示词：4K / 8K / 杰作 / 超清晰 / 大师作 / wallpaper 一类废话词（用物理材质词替代）
- 硬切转场、转场无时空交代
- 品牌植入：画面 / 语音 / 字幕三层都禁
- 未经批准烧积分；指令压缩/改写后出片
- 交付/发布不带 AI 生成显式标识、不主动声明；删除/篡改/伪造/隐匿标识（法定义务，闸 10）【官方：《人工智能生成合成内容标识办法》国信办通字〔2025〕2 号，2025-09-01 施行】

## 1. 花钱门（共享闸模块｜主责：出片检查，凡扣积分必过）

**花钱门是 `shared/` 里唯一共享闸模块。任何会扣积分的生成调用（生图 / 生视频 / 生音频 / 素材图），一律先过花钱门——素材图也不例外。**

操作程序（三步，顺序不可换）：

1. **报价**：生成前先 `node quote` 报价（单价 × 数量合计），把账单（总价上限 + 逐项明细）发给用户。
2. **用户批**：拿到用户**明确批准**后才允许执行。素材审查通过 ≠ 可以花钱——审查过的是「内容对」，批不批花钱是用户的事；批量/重制场景尤其禁止「反正矩阵对了就自己开跑」。
3. **跑**：批准后才 `--run`，执行时带上批准人与积分上限（`--approved-by` + ceiling）。缺批准信息一律拒绝执行。

**报价留余量（quote ≠ run）**：`node quote` 的报价可能显著低于 `--run` 实估（实测：quote 报 24/镜，run 实际 ≥56/镜，模型档位差）。因此：

- 账单按**实估上限**报给用户，留出档位差余量；
- **超账单必须重新获批**——实际支出逼近或超出已批上限时立即停下重新报价、重新获批，禁止拿着旧批文硬跑。

**职责边界**：`shot-qa` 只做检查与报价，不亲自执行生成；执行由各生成 skill 经花钱门直调目标后端工具（默认 dreamina-canvas，其他后端见 `shared/backends.md`）。**出片执行=自动为主，手动贴平台仅作备选路径**。违反花钱门 = 烧用户真金白银，零容忍。

## 2. Notion 唯一控制面（主责：出片检查）

- 数据记录 / 同步 / 更新 / 审核全部在 Notion 完成；文档只是事后笔记。
- **生成状态 = 「生成中」（即用户批准）才允许调用出图/出视频**，禁止绕过 Notion 审核直接调生成。
- Schema 沿用已验证字段契约（剧本表 / 人物表 / 资产节点 / 生成状态），每部剧一个新栏目，新增服装套与检查报告字段；**不做旧数据迁移**。

## 3. 零压缩铁律（主责：出片检查）

- Notion 里的指令 = 原始数据。出片时**逐字搬运**，禁止压缩、改写、拼装、加删标注头后再传。
- 以 SHA-256 校验搬运前后一致；本地拼装指令再传、把多段合成一段、给指令加/删标注头——全部违规（历史已犯过，见 `shared/lessons.md`）。

## 4. 结果验真（主责：出片检查）

- 报结果**只认提交时刻之后的新 resource**：看 **`submission.resources`**，不看 node 旧快照。
- 新 resource 的 `createdAt` 必须晚于本次提交时间戳；历史 success 资源一律不得当结果汇报。
- 轮询等待必须等新 resource 出现，禁止抓节点上第一条 success 交差。
- **验真走 `submission.resources` 自动回填 Notion**——验真结果自动写回 Notion 数据表，不做纯手工登记。

## 5. 一枪一停 / 原节点重跑 / 重制不夹带（主责：出片检查）

- **一枪一停**：一次生成只干一件事，出完验完再开下一枪。
- **原节点重跑**：重试在原节点/原指令上重跑，不另起炉灶换指令。
- **重制不夹带**：重制只重制目标产物，禁止夹带改动其他镜/其他资产的生成。

## 6. 广告植入闸（三层禁｜主责：分镜创作自检 + 出片检查扫描）

真实品牌在**画面 / 语音 / 字幕**三层全部禁止，包括：

- **真实品牌名**（词表见 `shared/brand-wordlist.txt`，台词 / 旁白 / 弹幕一并扫）
- **品牌感商品包装**：指令写死「素色无品牌 + 禁包装特写」
- **品牌 Logo / 商标字样**

出片前必须过品牌扫描（`tools/brand_scan.py` 三层文本各扫一遍），命中即打回，不许「化名绕过」。

**广告合规补充（2026-10-31 入库）**：

- **极限词红线**【官方：《广告绝对化用语执法指南》，市场监管总局 2023-02-25 发布】：广告法第九条第三项「**国家级、最高级、最佳**」及近似用语禁用于台词/字幕/贴片里的品牌宣传语；六类豁免情形（仅表经营理念/主观愿望、同品牌自我比较、消费提示、商品名称或注册商标本身含绝对化用语、评定奖项称号、限定时间地域的销量事实）可对照放行；医疗/医美/药品/保健食品、招商投资、教育培训广告**从严**，不属轻微违法。
- **广告可识别性**【官方：视频号运营规范 4.6.4】：品牌露出须让观众识别为广告（4.6.4 引《广告法》《互联网广告管理办法》），隐性营销被禁。
- **禁违规产品植入**【官方：《网络短视频内容审核标准细则》(2021) 第 99 条】；**避真实商标仿冒**【官方：视频号 3.4/3.5 仿冒品牌条款、快手规范五-3 盗用商标条款】——虚构品牌不得撞真实商标。

## 7. 转场交代规则（主责：分镜创作）

场景 / 时间变化的**进场镜**必须齐备两件：

1. **时空交代**：旁白「时间，地点，场景变化逻辑」或屏幕 UI 层字幕卡；
2. **转场过渡句**：写明空间延续（镜头从上场景空间延续摇入/推入等），**明写不硬切**。

同场景多镜共用同一套场景资产，保持空间 / 光影连贯。镜文没写 = 模型自由发挥 = 转场突兀，检查发现转场裸切直接打回。

## 8. 后端方言规格（默认：即梦 / Seedance；主责：分镜创作；方言表见 `shared/backends.md`）

- **单次生成 ≤15s**，超出自动分段；
- **中文提示词 ≤500 字**；
- **每时间片一个动作、一个运镜**（防画面抖）；
- **写实真人面部转 3D / cel-shaded**，防内容拦截；
- **情绪必须可视化**：「泪水滑落、嘴唇微颤」而非「她很伤心」；
- **禁废话词**，用物理材质词替代；
- 参考图默认走多参考图语义，明确说「当首帧」才走首帧路径；接戏用首尾帧（`first_last_frame`），绝不用整条视频做 ref。

## 9. 留存三主轴（既是产出标准，也是自检项）

1. **场景转场连贯**——转场必交代时间 + 地点 + 空间延续；同场景多镜共用同一套场景资产。
2. **剧情分镜**——钩子结构、节奏密度、镜头细切到可拼接。
3. **人物建模质量**——三视图锚点制资产 + 出图前置调研 + 风格库。

## 10. AI 生成内容标识闸（法定义务·交付/发布前｜主责：出片检查）

> **官方，最高优先级**【官方：《人工智能生成合成内容标识办法》，网信办/工信部/公安部/广电总局，国信办通字〔2025〕2 号，**2025-09-01 施行**（全文 xwb.neu.edu.cn/2025/0316/c9646a279035/pagem.htm 转载）；同款要求：微信视频号运营规范 6.4「AI 生成/合成内容须以显著方式标识」】。法定义务不因后端/项目变化而豁免，成片交付与发布前逐项过：

1. **显式标识**：视频须在**起始画面和播放周边**加显著提示（末尾/中间可选）；导出/下载的成片文件必须含显式标识。
2. **隐式标识**：文件元数据嵌入生成属性、服务提供者、内容编号；鼓励数字水印。
3. **发布主动声明**：发布生成合成内容须**主动声明**并使用平台标识功能；**禁止删除/篡改/伪造/隐匿标识**（传播平台须核验隐式标识并加「生成/疑似生成」提示）。

- 素材层出图关水印（`watermark=false`，见 `shared/backends.md`）≠ 成品免标识——中间素材不发布，**发布成品的显式标识义务由本闸兜底**。
- 交付清单检查项见 `skills/shot-qa`（交付前检查）；任一不过 = 拒绝交付/发布。

## 执行顺序总览（唯一顺序，任何环节不得调换）

**所有内容检查必须在报价之前完成**——「先检查再花钱」：内容有问题的镜连账单都不该出。

```
预检（全部内容检查，逐项过完才许报价）
  ├ 逐字搬运对账（闸 3 零压缩）
  ├ 转场交代检查（闸 7）
  ├ 广告植入扫描（闸 6 三层）
  ├ 违禁废话词 + 每镜 ≥250 字 + 看点/钩子落点
  ├ 素材挂载 + ref 格式（闸 3 素材校验 · 预跑部分）
  ├ Notion 状态 = 生成中（闸 2）
  └ 规格复核（闸 8：长度/分段/运镜/情绪/废话词）
→ quote 报价（闸 1 花钱门 · 账单发用户）
→ 用户批（明确批准 + 批准上限）
→ run 执行（一枪一停 / 原节点重跑 / 重制不夹带，闸 5；逐字搬运）
→ 验真（闸 4：submission.resources 自动回填 Notion，只认提交后新 resource）
→ 检查报告
→ 交付前：AI 标识检查（闸 10：显式/隐式/主动声明，交付与发布前必过）
```

## 出片五律（2026-10-29 用户令，最高优先级，凌驾本文件其他条款）

背景：58 积分因提示词被压缩改写+漏挂道具参考而作废。以下五条是出片链路的宪法：

1. **分镜即指令**：剧本/小说改编的分镜由虚拟导演产出；出视频必须**严格传递分镜内容**（四段式逐字节，唯一机械处理=换行归一化＋**剥离素材映射行/资源ID等生产数据**——这些走 `--ref` 参数通道，不进提示词正文，2026-10-30 用户令），禁止任何随意压缩/改写/自创描述块（`manju-pipeline/generation-workflow.md` L109 同源）。超模型上限=回 Notion 做设计变更，禁止传输时偷压。
2. **付费前审查**：任何真实扣费（confirm/run）前必须过 `tools/shot_gate.py` 全闸 + Notion「状态=生成中」审查记录；无审查记录不花一分钱。
3. **@素材真实绑定**：每镜按分镜设定逐个绑定 @素材参考图——不是「关联完就完了」，参考图必须就是该 @锁名登记的那张（含状态变体），人物走设定卡唯一入口，否则角色一致性必崩。
4. **素材-分镜数据一致**：生成时刻的素材映射以 Notion 素材台账为准（「分镜锁名」+「状态关键词」列），按镜内状态选对变体（示例占位：状态变体 A≠B，剧内状态词勿入 skill（2026-10-31 纪律））；映射必须一路钉到**画布实际素材**——生成调用传的 `res:` 资源 ID / 画布节点 ID 必须就是该 @锁名登记的那张，闸按 ID 逐个核对，防引用错误与 @ 取错。
5. **Notion 对齐**：数据流转全部过 Notion；本地镜块 ↔ Notion 内容列 SHA 级一致才准出片，生成包/审查记录/产物 ID 全部落 Notion。

执行件：`aigc-suite-skills/tools/shot_gate.py`（配置驱动，项目侧只留 `gen_gate.config.json`）。任一闸 FAIL = 拒绝生成，无例外。
