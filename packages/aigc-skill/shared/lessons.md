# 经验教训（lessons）

> 漫剧实战中逐条验证过的翻车点与解法，一句话教训 + 一句话解法。别再犯。
> 每条对应硬闸/工序的位置见括号标注；出图、出片前通读一遍。

## 1. i2i 锚构图

- **教训**：i2i 垫图会把参考图的视角与景别锚死（正视转 3/4、全身变膝上景），三视图转不动角度。
- **解法**：主体三视图用 t2i 文字控构图；i2i 只用于服装三视图/表情表/单人立绘，且必须挂主体三视图并写死构图硬锁句（单人单图、正常站姿）。（「忽略参考图排版」已删——与 character-asset-system.md 同步证伪，2026-10-28 xyq 实测）

## 2. 显老词

- **教训**：苹果肌饱满/御姐系一类词把 18 岁女主画成大妈。
- **解法**：建显老词黑名单（成熟女性/御姐/轻熟/知性/名媛/苹果肌饱满/清晰下颌线/细长眼/大波浪盘发/浓妆红唇/性感气场/法令纹眼袋），少女人设逐条对照禁用。

## 3. 服装漂移

- **教训**：服装只靠 prompt 硬写必漂——实测卫衣漂成裙装；身份与服装焊死一张图，换装全靠嘴说。
- **解法**：服装三视图 i2i 挂主体三视图（强制同光影、同站姿、同机位），全套逐件写死版型+颜色+鞋袜+配饰并写「图中标注」清单；分镜画面的服装描写与该镜服装套提示词段同源。

## 4. 表情抄外貌

- **教训**：表情表每格抄全外貌又臃肿又稀释表情差异（表情有效信息仅 2%【无来源】），四格同脸。
- **解法**：外貌/年龄/妆感/背景/风格只在布局头写一次，每格只写表情解剖（眉、眼、嘴、神态收束，25–40 字写满写差异）——同脸的解药是表情写满写差异，不是抄外貌。

## 5. video ref 塌缩

- **教训**：镜间挂 video ref（m2v）会让模型续写参考视频的构图+动作，整集塌缩成同一画面（002 犯过：7 镜链式重复）。
- **解法**：接戏转场用 first_last_frame 首尾帧，绝不用整条视频做 ref；video ref 只挂单人立绘当内容锚（i2i 提出角色、构图硬锁），设定卡/三视图永远不是视频素材。

## 6. quote ≠ run 报价

- **教训**：`node quote` 报价可能显著低于 `--run` 实估（实测案例：quote 报 24/镜，run 实际 ≥56/镜，模型档位差）。
- **解法**：账单按实估上限报价留余量；实际支出超账单立即停下**重新获批**，禁止拿旧批文硬跑（见 `shared/hard-gates.md` 花钱门）。

## 7. submission 验真

- **教训**：节点上的历史 success 资源被当结果汇报，交的是旧图旧片。
- **解法**：只认提交时刻后的新 resource——看 `submission.resources` 不看 node 旧快照，`createdAt` 必须晚于提交时间戳，轮询等到新 resource 出现才算数。

## 8. 转场裸切打回

- **教训**：转场镜没写地点+时间交代，模型自由发挥，转场突兀，检查直接打回。
- **解法**：场景/时间变化的进场镜必带旁白/字幕卡「时间，地点，场景变化逻辑」+ 转场过渡句（空间延续、明写不硬切）；剧本层写全、出片逐字搬运，A 轮检查加扫「转场镜缺地点/时间交代」。

## 9. 广告植入打回

- **教训**：画面/语音/字幕任何一层出现真实品牌名、品牌感包装或 Logo，成品直接打回。
- **解法**：三层都禁（画面/语音/字幕）——指令写死素色无品牌+禁包装特写，出片前用 `tools/brand_scan.py` 扫三层文本，命中即改（词表见 `shared/brand-wordlist.txt`）。

## 追加教训（同样别再犯）

### 10. 指令压缩/拼装打回

- **教训**：把多段指令压成合图段、本地拼装指令再传、给指令加/删标注头——全部违反零压缩铁律。
- **解法**：Notion 指令 = 原始数据，出片逐字搬运并 SHA-256 校验，任何「优化一下再传」都算违规。

### 11. Q 版 i2i 锚排版

- **教训**：Q 版 i2i 挂设定卡时，设定卡的三视图排版被整图锚定抄走，一句「忽略参考图排版」压不住。
- **解法**：Q 版提示词必须显式禁止多视图/版式（禁三视图、禁宫格排版、禁标注引线、禁全身比例图），构图硬锁为单人单图正面站立。

### 12. 表情 6 字碎片

- **教训**：表情只写 6 字碎片（「唇角极浅上扬」）→ 四格表情无差异、同脸崩。
- **解法**：每格表情解剖写满（眉+眼+嘴+神态收束 25–40 字），写满写差异才是同脸解药。

### 13. 双人镜漏挂对手

- **教训**：双人镜只挂主角 → 对手角色缺失；场景节点存在但漏挂 → 特效层缺失。
- **解法**：生成前过素材矩阵审查——镜内每个出场人物逐人挂资产、场景必挂，审查不过禁止生成（对应检查报告 `素材校验.挂载`）。

## 行业常见坑（2026-10-28 用户供）

- **教训**：不做人设卡直接 AI 出图。**解法**：人设卡完整字段先行（外貌固定设定/禁止项/表情库），出图全部挂参考。
- **教训**：场景不做光影规范，白天黄昏乱切。**解法**：每景光影四件套锁定值逐镜复制。
- **教训**：名片随便加、重复弹出。**解法**：出场顺序表策划层标记，每角色恰好一次。

## Notion 接口坑（2026-10-28 实测）

- **教训**：`notion-delete-pages` 假成功——参数名是 `page_ids`（`pages` 静默无效）；且删除需**用户显式确认**，必须带 `user_confirmed: true`，否则 API 400 挡回；批量删除数组有上限（大数组报 Too big，按 ≤10 一批）。
- **解法**：删除前先向用户展示删除清单拿确认，调用带 `user_confirmed: true`，批量 ≤10，逐批核对返回 `isError`。
- **教训**：`notion-create-pages` 挂数据库行必须用 `parent.data_source_id`（collection:// URL）——用 `database_id` 挂法**静默失败**（返回 OK 但行不进表，沦为孤儿页）。
- **解法**：入库后必须 COUNT 复核行数，不信 create 的 OK。
- **教训**：Query Data Source 有 workspace 配额（SQL/rows 模式），耗尽后 60 分钟才恢复；view 模式不受限但需合法 view URL。
- **解法**：批量灌表用 create 通道不占查询配额；校验计数省着用；配额挂了挂后台任务等重置。
- **教训**：`SELECT ... LIMIT/OFFSET` 翻页可能**静默漏行**——COUNT(*) 说 303 行、分页 SELECT 只见 302，漏的那行逃过批量清理（薄行清理漏删 006-13，靠收尾 COUNT 对账才抓到）。
- **解法**：批量操作收尾必须 **COUNT 复核 = 预期数**；对不上就按「内容特征反查残留行」（如 `WHERE 内容 NOT LIKE '%四段式标记%'`）定位补刀，不要只信翻页清单。
- **教训**：SQL 配额窗口可能**极浅**（一次 COUNT 后紧接着的 SELECT 就爆 allowance）——批量同步/更新绝不能靠 SQL 查行 ID。
- **解法**：①`notion-create-view` 建排序视图拿 `view://` URL → `query-data-sources` **mode=view 免配额**取全量行 → 集数→page_id 映射缓存本地（row_map.json）②后续更新全走 `update-page`（不占查询配额），批量脚本零查询可跑 ③新建表时顺手把 create 返回的行 URL 落盘，一步到位。

## xyq 出图实测（2026-10-28 · 智能图片V2.5 Pro）

- **教训**：i2i **参考图排版锚定**——挂三视图出单人立绘，输出原样复刻参考图的宫格排版（三格+左上特写格），「忽略参考图排版」「中景半身到膝」文字指令全被无视。
- **解法**：构图锁改**正面画框描述**（仅一名人物/仅一个画面格/无分格/无画中画）+ 取景下缘写死切点；顽固时参考图先裁单人格，或立绘改 t2i 靠锚点短语保同脸。骨架见 `character-prompts.md` §1.7。
- **验证**：t2i 显式排版锁（逐格定位）一次过——三视图/变异体结构锁/场景光线四件套精度全达标，指令体系（锚点短语+构图锁+负面正向段）在该后端可靠。
- **工具坑**：`query-result` 输出**多行 JSON**——`tail -1` 截断后永远解析失败、轮询空转；整段 stdout 交 `json.loads`。
- **成本口径**：智能图片V2.5 Pro 1K/high ≈ **6 积分/张**；余额查询 `pippit-tool-cli get-credit-balance`（只读）。

## 品牌扫描语境判断（2026-10-28 剧本机检）

- **教训**：品牌词表会误伤普通义词（「统一收缴」的「统一」）与品类词（「辣条」），一票否决会卡死机检。
- **解法**：命中后先看语境——①普通义（动词/形容词）直接换近义词保零噪音（「统一收缴」→「集中收缴」）②品类词在有版权前科的剧目（曾被点名的食品场景）从严处理，换成世界观内物品（「辣条」→「压缩饼干」）并保住角色语气 ③真正的品牌植入才按硬闸拒稿。

## 微恐/惊悚描述的平台审核规避（2026-10-28 xyq 倒吊影被拦实测）

- **教训**：「诡异生物/无瞳大眼/瘦长人形/半透明皮肤可见筋腱/无服装」组合会被平台内容审核判为惊悚低俗**拦截**（生成空产物，连试 4 次全拦，Fast/Pro 同样拦——换模型没用，是审核不是模型）。
- **解法（中性化词表）**：诡异→奇幻/幻想；无瞳大眼→浅色大眼睛/浅灰双眼；筋腱/半透明皮肤→细腻纹理/薄纱质感；瘦长人形裸露→**加遮蔽物**（缠身破布/薄膜斗篷/紧身覆盖躯干）；惊悚形容词整体降浓度（删「僵硬/空洞/腐」类字眼）；恐怖头部特写板 6 格可减至 3 格；先简化排版过审再补细节。
- **模型纪律（2026-10-28 用户定）**：测试与常规出图一律 **V2.5 Fast**；Pro 仅在用户点名时用——「Pro 经不起测试」。


## Notion 建行/状态选项坑（2026-10-29 实测）

- **create-pages 挂库行的 parent 位置**：`parent` 是**顶层参数**（`{'type':'data_source_id','data_source_id':...}`），塞进单页对象里报 `Unrecognized key: "parent"`。
- **「状态」列选项缺失 = 400 validation_error（报错体截断，极难看出真因）**：素材台账/分镜表的 status/select 列写入不存在的选项（如「生成中」）会连环 400。解法：先 `update-data-source` `ALTER COLUMN "状态" SET STATUS/SELECT(...)` 扩选项再写。两表口径已统一：素材台账=待补/生成中/已生成/已验收；分镜表=待出片/生成中/已出片/重生成（「生成中」即用户批准的生成门）。
- **网络抖动放大排查成本**：`SSL: UNEXPECTED_EOF_WHILE_READING` 高频出现，MCP 调用必须带重试壳（8 次×10s）；网络错误与业务报错要分开打印，别混在重试里吞掉真因。

## 画布临时节点纪律（2026-10-29 用户发火实测）

- **教训**：为比价/探价在用户素材库画布上建「比价-xx」临时节点，比完没删——污染用户画布，用户直接发火。创建/编辑/报价节点都不扣积分，但**节点是用户可见资产，不是我的草稿纸**。
- **纪律**：任何探针/比价/试验节点**用后即删**（三步删除），或干脆建独立临时画布；交付前 `node find` 复核用户画布只剩应有节点。
- **删除三步新坑**：`node delete` 的 confirmation_required 响应输出在 **stderr**（ok=false），stdout 为空——解析 stderr 取 `deletionConfirmation.updateId`，再 confirm 签 token → delete --delete-token 执行。批量删除含不存在的节点会整批拒绝（target_not_found），先 find 核对再删。

## Notion 内容列往返归一化（2026-10-29 G-PARITY 实测）

- **坑**：镜文写入 Notion 再读回，文本会被归一化：换行→`<br />`、下划线等字符→markdown 转义（`\_`、`\*`）。逐字比对直接比 SHA 必然误报不一致。
- **解法**：比对/取回前做**双向机械还原**（属唯一允许的机械处理）：`<br />`→换行、`\<char>`→char、行尾空白trim、`\r\n`→`\n`。工具实现见 `tools/shot_gate.py:norm()`。
- **配套**：G-PARITY 闸=本地镜块↔Notion 内容列归一化后 SHA 级一致才准出片；生成提示词的唯一合法来源=`--emit-prompt`（从 Notion 内容列逐字取出还原后落盘，调用只准 `$(cat prompt.txt)`）。

## 校验=合规不是限创作（2026-11-05 用户令）

用户原话：「你所有的产出，检查，校验，是合规而不是限制模型，限制发挥，限制创作。」

- 一切检查器/硬闸/自检项只拦合规风险（平台审核、品牌、法定义务、资损、拼装手误、机器不可读），不拦创作自由（字数、风格、叙事、镜头语言）。

## 分镜时间≠模型时间：时间轴必须对时（2026-11-05 成片 ffprobe 实测）

成片时长精确=生成参数 durationSeconds，指令时间码只是节奏指引——时间覆盖超出部分被模型压缩/砍掉（实测 8.0s 覆盖→4.06s 成片、12.5s→8.06s）。12 条实证仅 3 条严格对时，此前自检只查时间码「格式」不查「对时」=缺口。已补 ⑦ 对时机检（--duration）：总长=生成时长±0.5s；时间轴全篇统一（视频轴 00:00 起算推荐 / 剧本轴禁混用）；快切镜按 4s 出剪辑裁短。

1. **人物比例侏儒感 + 妆容不真实**：旧风格档案只写「二次元五官比例（大眼睛、小脸）」不锁头身比 → seedream_4.5 全员 5–6 头身短腿幼态；旧妆容口径「淡红眼妆+红唇」被模型放大成浓重眼影+大面积腮红。回写：new-chinese-3d-anime-spec.md 加**身材头身比硬锚（7–8 头身修长、腿身比正常，大眼小脸只管五官绝不管身材）**+ 妆容改口径为**真实接近真人日常淡妆**（禁彩色/红色眼影、禁明显腮红团，像真人化妆不像舞台妆）；character-prompts.md §1.1 模板主体段强制含头身比。根因=三渲二是「日漫的脸、3D 的质感」，但**身材走真人时装比例**，五官动漫化不等于身材 Q 版化。
2. **三视图版式翻车**：头部特写要 4 格（头正面/3-4 侧/后脑/眼部极特写）结果只出 3 格，全身区额外多出第 4 张人物图。seedream_4.5 对 7 格宫格同样不守恒（实测「左4全身+右3特写」「左3右3」两形态）。回写：设定卡版式**定死 7 格左3右4**，头部特写 4 格缺一即废、全身多出即废（覆盖 2026-11-06「7–8 面板弹性」）；落点 new-chinese-3d-anime-spec.md 排版媒介、character-prompts.md §1.1+排版强化、multiview-creature-spec.md 版式条。
3. **出视频指令未按 skill 走 + 分镜出片需有序命名**：T4 判 0 分（见 material-live 测试文档 §八）后用户再次强调。回写：video-producer SKILL.md 新增**「出片指令唯一来源」硬闸**——出片提示词只能按 storyboard-director prompt-format §九 四段式镜块产出，禁止手写散文，prompt_selfcheck 机检通过 ≠ 按 skill 走；素材库命名改**有序命名 `NNN_<分镜描述>_xx.mp4`**（NNN=三位数 001 起按分镜顺序，导入剪辑软件按剧情时间天然排序），同步 production-workflow.md §四。
